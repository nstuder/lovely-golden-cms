# lovely-golden CMS

Official website for lovely-golden.de using Payload CMS 3, Next.js (App Router, React Server Components) & Tailwind CSS 4.

Requires Node.js `^22.23.5`, `^24.22.3` or `>=26.13.1`.

## How to Use

- `npm run dev` – Next.js dev server (website + admin at `/admin`)
- `npm run build` / `npm start` – production build / server
- `npm test` / `npm run test:watch` – unit & component tests (Vitest + Testing Library)
- `npm run lint` – ESLint (formatting is left to Prettier: `npx prettier --write .`)
- `npm run generate:types` – regenerate `src/cms/payload-types.ts` after changing collections
- `npm run generate:importmap` – regenerate the admin import map after adding admin components

Environment (`.env`): `MONGODB_URI`, `PAYLOAD_SECRET`, `BASE_URL`.

## Structure

- `src/cms` – Payload config, collections, globals, blocks, admin components
- `src/app/(frontend)` – public website routes: load data and render a template
- `src/app/(payload)` – Payload admin + REST/GraphQL API (generated by Payload)
- `src/components` – website components following [Atomic Design](https://atomicdesign.bradfrost.com/chapter-2/):
    - `atoms` – smallest building blocks (image, carousel controls, tab link, logo)
    - `molecules` – simple groups of atoms (rich text, teaser cards, pagination, tables)
    - `organisms` – page sections (navigation, header, footer, gallery, pedigree, content blocks, tabs)
    - `templates` – page layouts that only receive data as props (dog detail, news list, …)
    - `pages` – shared pages that load their own data (CMS page fallback, paginated news)
    - `behaviors` – client-side hooks without markup (carousel, URL hash)
- `src/lib` – data helpers (Payload client, metadata, links, formatting)
- `src/styles/main.css` – Tailwind CSS (theme: colors, fonts, content widths, rich text), imported by the frontend layout

Every level only uses components from lower levels (or its own level). Each level
has an `index.ts`, so imports look like `import { Image } from '@/components/atoms'`.

## Live Preview

Pages, dogs, litters, galleries, news and the home page have a live preview in
the admin (eye icon in the document view). It shows the document with the
website's templates and updates while typing, before saving. The preview page
(`/live-preview/<collection>/<id>`) is only available to logged in admins and is
not indexed.

## Tests

Tests live next to the code (`*.test.ts(x)`). Components are rendered with
Testing Library in jsdom; for data loading only the Payload client is mocked
(`src/test/payloadMock.ts`), so the real helpers in `src/lib` are tested as well.
Shared test data is in `src/test/fixtures.ts`.

## Deployment

`cd deploy && ansible-playbook -i hosts deploy-playbook.yml` pulls `main` on the
server and rebuilds/restarts the website container (MongoDB keeps running).
Backups: `./backup.sh` on the server (database dump + uploads).

Both containers restart after a crash or reboot (`restart: unless-stopped`) and
have a healthcheck (website: `/healthz`, checks the database too). The website
runs as user `node` (uid 1000), so `media/` must belong to uid 1000; the
playbook takes care of that.

Secrets are never part of the image (`.dockerignore`):

- `.env` (website): `PAYLOAD_SECRET`, `BASE_URL`, `MONGODB_URI`. Payload uses
  its own MongoDB user with `readWrite` on the `payload` database only.
- `mongo.env` (MongoDB only): `MONGO_INITDB_ROOT_USERNAME/PASSWORD`, used by
  `backup.sh` and for maintenance.

`deploy/mongo-app-user.sh` set this up once (creates the user, splits the
files). Running it again sets a new password for the app user.

Caching: the website caches its CMS queries (`src/lib/payload.ts`); every
change in the admin clears that cache (`src/cms/revalidate.ts`).

MongoDB runs as `mongo:8.0.38` (upgraded from 4.4 with `deploy/mongo-upgrade.sh`,
which steps through 5.0, 6.0 and 7.0). Neither MongoDB nor the website publish a
port; Traefik reaches the website via the `traefik` network.

## Upgrade from Payload 2 (Express)

The database stays as it is, no migration is needed to run the site.
Old upload URLs (`/media/<file>`) are rewritten to Payload 3's `/api/media/file/<file>`.

Optional: `src/migrations` contains Payload's official one-time migration that
converts relationship IDs from strings to ObjectIds (only relevant for filtering
by relationship fields in the admin). Make a backup first (`./backup.sh`), then
run `npm run payload migrate`.
